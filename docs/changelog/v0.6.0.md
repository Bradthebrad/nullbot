# NullBot v0.6.0

Secrets in an encrypted vault, several chats at once, your own model servers,
Claude through your subscription, and cloud machines you approve. NullBot's
desktop app ([NullBot UI v0.6.0](https://github.com/Bradthebrad/nullbot_ui/releases/tag/v0.6.0))
is built on this version.

## Highlights

- **Secrets vault.** Every credential (model API keys, the ChatGPT sign-in,
  GitHub tokens, SSH keys, AWS and Google Cloud credentials, anything else)
  is kept encrypted in `~/.nullbot/vault`, protected by Windows DPAPI, the
  macOS keychain, the Linux Secret Service or, on servers, a passphrase.
  Plain-text key files from older versions move in on first use. Agents use
  a secret without seeing it: `secret_run` runs a command with the secret in
  its environment and removes the values from what it prints. GitHub
  sign-in, `nullbot secrets ssh-keygen`, and `nullbot secrets`/`nullbot
  vault` on the command line. See [docs/SECRETS.md](https://github.com/Bradthebrad/nullbot/blob/main/docs/SECRETS.md).
- **Several chats at once.** Each chat has its own conversation, queue, run
  controls and subagents, sharing the configuration, projects, tool servers
  and vault. The main chat lists, reads, steers, pauses and opens the others.
  See [docs/CHATS.md](https://github.com/Bradthebrad/nullbot/blob/main/docs/CHATS.md).
- **Claude through the `claude` command.** The Claude CLI provider uses your
  Claude subscription through your installed Claude Code: what Claude writes,
  thinks and does streams in like NullBot's own steps, and its tools follow
  each project's permissions. See [docs/CLAUDE_CLI.md](https://github.com/Bradthebrad/nullbot/blob/main/docs/CLAUDE_CLI.md).
- **Your own model servers.** Ollama, llama.cpp, LM Studio, vLLM or any
  OpenAI-compatible server, here or on another machine, as providers
  `local:<id>`. NullBot learns the context each model really runs with and
  can make a larger-context Ollama copy. A server's key is tied to that
  server, never follows a redirect elsewhere, and goes over plain http to
  another computer only if you allow it.
- **Which models run well here.** A Go port of
  [llmfit](https://github.com/AlexsJones/llmfit) ranks 1,435 models for this
  computer's CPU, memory and GPU (`nullbot models fit`), and models install
  from Hugging Face into Ollama, LM Studio or a folder (`nullbot models
  search`, `install`). See [docs/LOCAL_MODELS.md](https://github.com/Bradthebrad/nullbot/blob/main/docs/LOCAL_MODELS.md).
- **Cloud machines and storage you approve.** AWS and Google Cloud through
  the official `aws` and `gcloud` CLIs. Every change is a plan of exact
  commands with its hourly cost; nothing runs until a person approves it
  (in the desktop app, or by typing the plan's code at a terminal), and the
  approval is sealed, so only those commands run. Every command goes in a
  ledger; NullBot only removes what it made. Machines can set up NVIDIA
  drivers, Ollama and a headless NullBot on first boot, and `nullbot infra`
  shows what runs where, opens tunnels and connects a machine's model here.
  Agents can propose plans when you allow it, never approve them. See
  [docs/INFRA.md](https://github.com/Bradthebrad/nullbot/blob/main/docs/INFRA.md).
- **More headless options.** `--subagent-model`, `--effort`,
  `--max-iterations`, `--max-subagents`, `--continue` / `--session`,
  `--timeout` (exit status 124) and `--output`, and `--json` says which
  session a reply was saved to. See [docs/HEADLESS.md](https://github.com/Bradthebrad/nullbot/blob/main/docs/HEADLESS.md).

Built on [tinychain v0.4.0](https://github.com/Bradthebrad/tinychain/releases/tag/v0.4.0):
models that run their own tools report commentary and steps as they stream.

## Downloads

| File | Platform |
| --- | --- |
| `nullbot.exe` | Windows x64 |
| `nullbot-small.exe` | Windows x64, compressed with UPX for a smaller download |
| `nullbot-windows-arm64.exe` | Windows on Arm |
| `nullbot-linux-amd64` | Linux x64 |
| `nullbot-linux-arm64` | Linux on Arm |
| `nullbot-darwin-amd64` | macOS on Intel |
| `nullbot-darwin-arm64` | macOS on Apple silicon |
| `SHA256SUMS.txt` | SHA-256 checksums for all of the above |

Each file runs the terminal UI, or headless with `-p` or `serve`. On Linux
and macOS, make the file executable (`chmod +x`); macOS may need the download
quarantine removed (`xattr -d com.apple.quarantine nullbot-darwin-arm64`)
because the binaries aren't signed. Antivirus tools and SmartScreen
sometimes flag UPX-compressed executables; if `nullbot-small.exe` is blocked,
use `nullbot.exe`. The desktop app is a separate download.

## Upgrading

- API keys and the ChatGPT sign-in move from `api/keys.json` and
  `api/codex_auth.json` into the vault the first time NullBot runs; the old
  files are overwritten and deleted once everything is in. On a server
  without a keychain, set `NULLBOT_VAULT_PASSPHRASE` (or
  `NULLBOT_VAULT_PASSPHRASE_FILE`) before the first run.
- Cloud plans and agent cloud tools are new and off by default.

## Validation and limitations

Checked for this release: the Go test suites of NullBot and tinychain on
Linux (with the race detector on the vault, cloud, local-model and
run-control packages), vet for Windows and macOS, cross-compiled builds for
all seven files, a headless smoke test of `version`, `help`, `models` and
`infra`, and independent reviews of the vault, the Claude CLI provider, the
local-model servers and (twice) the cloud work, with every finding fixed or
documented. Cloud
plans were exercised against fake `aws`, `gcloud` and `ssh` programs, not
live accounts; live providers, the Claude CLI and the terminal UI on each
platform were not exercised by these checks. An agent you also let run any
program acts as you, so it could approve a cloud plan the way you would in a
terminal (see INFRA.md).
